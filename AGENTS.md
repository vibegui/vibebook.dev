# vibebook

Project room: https://vibebook.dev/b/f94aedb83899 (report progress there: see the plugin's `vibebook` skill).

Browser architecture: `public/app.html` is the shell; `public/app.css` holds styles; typed Svelte room views and Vite entries live in `svelte/`. Existing integrations remain in `svelte/legacy/host.js`. Shared WS/HTTP contracts live in `shared/`; backend implementation stays in `src/`. See `docs/client-server-boundary.md`. Run `bun run build:ui` and commit every generated `public/svelte/*.js` chunk after frontend/shared changes. `bun run check:ui`, `test:ui`, `test:store`, `check:protocol`, and `check:client-boundary` verify this boundary.

Chat + tasks for people's Claudes to work together on projects: each vibebook = doc + group chat + epics/tasks (kanban) + decision log, people connect their own Claude (the product assumes it: until you do, the home and every room lead with a setup card), and `@vibe` is the room's housekeeper and grader, not a chat assistant (Nov 2026: mentioning @vibe no longer gets an answer).

- `src/index.ts` — Hono Worker: own auth (`src/auth.ts`: email 6-digit code via Cloudflare Email Sending + optional one-click Google and GitHub OAuth (`/auth/google/*`, `/auth/github/*`: state in a cookie, the provider's verified email (GitHub: primary + verified from `/user/emails`), name filled when empty; each button shows on the login only when its `*_CLIENT_ID`/`*_CLIENT_SECRET` secrets exist, `/auth/providers`; errors land on `/login?error=google|github`), HMAC session cookie), D1 index (users, books, members, friends), serves `/app` + `/b/*` shell, forwards `/ws/:id` to the book's DO.
- `src/book.ts` — `Book` Durable Object (SQLite): messages per thread (`main` or epic id), epics, tasks, doc; WebSocket hibernation; debounced alarm (30s after a message or board change): mention mail, housekeeping nudges, `findWaits`, `grade`, then classify (title/folder/summary/epic suggestions) with `MODEL_CLASSIFY`.
- @vibe = Jev (`src/jev.ts`, TypeSafe's decision model `MODEL_JUDGE` = `~typesafe/jev-latest` via OpenRouter `POST /api/alpha/decisions`, same setup as decoindex/circulei: typed `noul`/`score` questions, input-only billing, ~1s, ~US$0.00002 per call; `"off"` disables). `grade()`: per epic whose title/goal/tasks changed (hash in DO `grades`, ≤3 per pass, one call each): tasks cover the doc's goal (skipped while the goal is the seed text)? each task has a checkable done criterion? is one thing? does any task check that it worked (else "sem verificação" on the epic)? Answers <0.35 become `flags` on the epic/tasks (`epics()`), shown as ⚠ chips in the app (`vibeNotes`) and as `vibe_notes` in `read_room`, so the Claude that picks a task up gets the gap with it; never changes the board. The room doc is graded too (grade row `_doc`, first in the pass, counts toward the 3 calls; the alarm wakes 30s after a room-doc edit): objective specific (what, for whom), scope (in/out), success criterion, next steps/owners; misses become `doc_notes` (`docNotes()`, state `docNotes`, WS `docNotes`, chips on top of the room doc preview, `read_room.doc_notes`); a doc under 120 chars gets "doc quase vazio" without a call. `create_room` (description + its `next` field, llms.txt, `/vibebook:setup`) tells the agent to read the project, write the doc and start 2–4 epics right away, then sharpen what @vibe flags. `findWaits()`: each new message (≤20 per pass, last 7 days, from `waits_at_id`) gets one call: per other member, "does it ask X for a reply/decision/approval/review/action" (≥0.7 → D1 `waits` row ref `m<id>`), and per open wait on the author in that thread, "does it answer it" (≥0.6 → delete). Tasks in review with an owner are `t<id>` rows, rewritten in `epicsChanged` (archived epics drop their waits). Read side `waitsFor()` (`src/rooms.ts`): home: each room card lists its own waits ("Esperando você", 3 then "+N", ✓ = `POST /api/waits/resolve`, asks only; the total sits in the greeting line; cards follow the rail order, no @vibe folders; the phone keeps one list in the ☰ drawer), yellow count on rail tiles and, inside the room, on the sidebar row of each thread that has one (`waitsIn`/`waitPill`, tinted row, a ring on the collapsed rail) with the message itself marked "⏳ esperando você" (`.waitMsg`; re-rendered when the 30s `/api/me` refresh changes this room's waits), MCP `pending` / `resolve_pending`. Events `grade`, `waits` (cost), `wait_resolved`. Checks (local dev, tagged test users): the scratch scripts in the Nov 2026 session; `bun scripts/agent-check.ts` covers the tool list.

- Claude asks in the room (Nov 2026): the plugin's `PermissionRequest` hook (`claude-plugin/hooks/permission.sh`, timeout 630s, linked repos only) posts "⏸ Seu Claude pede permissão: <tool> · <verb (action/operation/method)> · <Bash description>" + `<the command or path, else every short field as key: value, ≤220 chars>` (one field alone hid an Artifact delete as just a URL) with choices Aprovar/Negar, waits for its human's pick with MCP `permission_wait` (`Book.answerTo`, ≤50s per call, up to `VIBEBOOK_PERMISSION_WAIT`=600s) and returns allow/deny to Claude Code; no answer = the usual terminal prompt (and the Notification hook's ⏸ blocked ack).
