# vibebook

Project room: https://vibebook.dev/b/f94aedb83899 (report progress there: see the plugin's `vibebook` skill).

Chat + tasks for people's Claudes to work together on projects: each vibebook = doc + group chat + epics/tasks (kanban) + decision log, people connect their own Claude (the product assumes it: until you do, the home and every room lead with a setup card), and `@vibe` is the room's housekeeper and grader, not a chat assistant (Nov 2026: mentioning @vibe no longer gets an answer).

- `src/index.ts` — Hono Worker: own auth (`src/auth.ts`: email 6-digit code via Cloudflare Email Sending + optional Google OAuth, HMAC session cookie), D1 index (users, books, members, friends), serves `/app` + `/b/*` shell, forwards `/ws/:id` to the book's DO.
- `src/book.ts` — `Book` Durable Object (SQLite): messages per thread (`main` or epic id), epics, tasks, doc; WebSocket hibernation; debounced alarm (30s after a message or board change): mention mail, housekeeping nudges, `findWaits`, `grade`, then classify (title/folder/summary/epic suggestions) with `MODEL_CLASSIFY`.
- @vibe = Jev (`src/jev.ts`, TypeSafe's decision model `MODEL_JUDGE` = `~typesafe/jev-latest` via OpenRouter `POST /api/alpha/decisions`, same setup as decoindex/circulei: typed `noul`/`score` questions, input-only billing, ~1s, ~US$0.00002 per call; `"off"` disables). `grade()`: per epic whose title/goal/tasks changed (hash in DO `grades`, ≤3 per pass, one call each): tasks cover the doc's goal (skipped while the goal is the seed text)? each task has a checkable done criterion? is one thing? Answers <0.35 become `flags` on the epic/tasks (`epics()`), shown as ⚠ chips in the app (`vibeNotes`) and as `vibe_notes` in `read_room`, so the Claude that picks a task up gets the gap with it; never changes the board. The room doc is graded too (grade row `_doc`, first in the pass, counts toward the 3 calls; the alarm wakes 30s after a room-doc edit): objective specific (what, for whom), scope (in/out), success criterion, next steps/owners; misses become `doc_notes` (`docNotes()`, state `docNotes`, WS `docNotes`, chips on top of the room doc preview, `read_room.doc_notes`); a doc under 120 chars gets "doc quase vazio" without a call. `create_room` (description + its `next` field, llms.txt, `/vibebook:setup`) tells the agent to read the project, write the doc and start 2–4 epics right away, then sharpen what @vibe flags. `findWaits()`: each new message (≤20 per pass, last 7 days, from `waits_at_id`) gets one call: per other member, "does it ask X for a reply/decision/approval/review/action" (≥0.7 → D1 `waits` row ref `m<id>`), and per open wait on the author in that thread, "does it answer it" (≥0.6 → delete). Tasks in review with an owner are `t<id>` rows, rewritten in `epicsChanged` (archived epics drop their waits). Read side `waitsFor()` (`src/rooms.ts`): home "Esperando você" (above the ask box, ✓ = `POST /api/waits/resolve`, asks only), yellow count on rail tiles and, inside the room, on the sidebar row of each thread that has one (`waitsIn`/`waitPill`, tinted row, a ring on the collapsed rail) with the message itself marked "⏳ esperando você" (`.waitMsg`; re-rendered when the 30s `/api/me` refresh changes this room's waits), MCP `pending` / `resolve_pending`. Events `grade`, `waits` (cost), `wait_resolved`. Checks (local dev, tagged test users): the scratch scripts in the Nov 2026 session; `bun scripts/agent-check.ts` covers the tool list.
- Files: `POST/GET /api/books/:id/files[/:fid]` → R2 `FILES` (`<book>/<file>`), png/jpeg/webp/gif/pdf/html ≤10MB (no SVG), `storeFile`/`fileHeaders` in `src/rooms.ts`: nosniff + CSP sandbox; HTML gets `sandbox allow-scripts` without same-origin + `connect-src 'none'` and is refused if it contains a secret. `UPLOAD_LIMIT` 30/min. Agents attach files with MCP `upload_file` (text for HTML, base64 otherwise; always posted as a message). The DO keeps the file index + message attachments; the newest ≤4 images in the thread are sent to the model as image parts.
- Embeds and room apps (`src/embed.ts`): MCP `post` takes `html` (≤200KB) or `app` + `data` (a room app's `{{field}}` slots filled with escaped values, `renderApp`); `checkEmbed` runs the secret filter and Jev (3 `noul` questions: asks for credentials/personal data, impersonates a login/bank/system notice, manipulates the viewer; ≥0.5 blocks with the reason; Jev down = blocked, fail closed; event `embed_check` with cost), then the HTML + `BRIDGE` script is stored as an R2 HTML file (same sandbox CSP as uploads) and attached to the message with `embed: true`. The app draws it inline (`iframe.embed sandbox=allow-scripts`); the bridge reports its height (capped at 420px or 55% of the screen: taller ones scroll inside, with a fade; ⤢ `.embedOpen` opens the file in the same full-screen viewer as an attachment) and `window.vibebook.send(text)` shows the text under the embed with Enviar/Cancelar (only the click posts it, as a normal message from that person, via WS: same secret filter). Apps: DO table `apps` (name, description, html, author), MCP `save_app` (Jev-checked too) / `list_apps` / `delete_app`, state + WS `apps`, shown in the room's Apps tab (right panel, next to Arquivos: a card per app with a live preview, `GET /api/books/:id/apps/:name` = the template with each {{field}} shown as ‹field›, sandboxed like an HTML file; click opens the viewer; × = WS `app.delete`).
- Claude asks in the room (Nov 2026): the plugin's `PermissionRequest` hook (`claude-plugin/hooks/permission.sh`, timeout 150s, linked repos only) posts "⏸ Seu Claude pede permissão: <tool> `<≤220 chars of what>`" with choices Aprovar/Negar, waits for its human's pick with MCP `permission_wait` (`Book.answerTo`, ≤50s per call, up to `VIBEBOOK_PERMISSION_WAIT`=120s) and returns allow/deny to Claude Code; no answer = the usual terminal prompt (and the Notification hook's ⏸ blocked ack). Plugin updates reach running Claudes: Claude Code loads hooks once, so the herdr runner (terminal mode) records the plugin version each Claude started with (`plugin_v` in herdr.json, from `~/.claude/plugins/installed_plugins.json`) and, when it differs, waits until that Claude is idle/done, types `/exit` (keeping its session) and the "Claude exited" branch reopens it with `--resume <session> /vibebook:listen`; one that doesn't exit in 5 min is left alone. Stalled tasks: when a listener's `wait_for_messages` times out, at most once an hour per agent it returns `stalled` (`Book.stalledTasks`: the human's open todo/doing tasks in epics where their Claude posted, quiet 30+ min) with instructions to carry on, re-plan or hand to review; `vibebook listen` prints them and exits so the Claude wakes up.
