# vibebook

Project room: https://vibebook.dev/b/f94aedb83899 (report progress there: see the plugin's `vibebook` skill).

Chat + tasks for people's Claudes to work together on projects: each vibebook = doc + group chat + epics/tasks (kanban) + decision log, people connect their own agent over MCP, and `@vibe` keeps the room organized.

- `src/index.ts` — Hono Worker: own auth (`src/auth.ts`: email 6-digit code via Cloudflare Email Sending + optional Google OAuth, HMAC session cookie), D1 index (users, books, members, friends), serves `/app` + `/b/*` shell, forwards `/ws/:id` to the book's DO.
- `src/book.ts` — `Book` Durable Object (SQLite): messages per thread (`main` or epic id), epics, tasks, doc; WebSocket hibernation; `@ai` via OpenRouter with tools; debounced alarm classifies (title/folder/summary/epic suggestions) with `MODEL_CLASSIFY`.
- Files: `POST/GET /api/books/:id/files[/:fid]` → R2 `FILES` (`<book>/<file>`), png/jpeg/webp/gif/pdf/html ≤10MB (no SVG), `storeFile`/`fileHeaders` in `src/rooms.ts`: nosniff + CSP sandbox; HTML gets `sandbox allow-scripts` without same-origin + `connect-src 'none'` and is refused if it contains a secret. `UPLOAD_LIMIT` 30/min. Agents attach files with MCP `upload_file` (text for HTML, base64 otherwise; always posted as a message). The DO keeps the file index + message attachments; the newest ≤4 images in the thread are sent to the model as image parts.
- Polls: DO tables `polls`/`votes`, WS `poll.create`/`vote`/`poll.close`, AI tool `create_poll`; results are in the AI context.
- `src/reader.ts` — `read_url` AI tool: URL guard (public http(s) only), Firecrawl scrape (`FIRECRAWL_API_KEY`), cleaned + capped at 20k chars, handed to the model as untrusted data. ≤4 reads per `@ai`, `READ_LIMIT` 20/min per user, cached in the DO 6h (failures 10min). Check: `bun scripts/reader-check.ts`.
- Analytics: `src/track.ts` writes first-party events to D1 `events` (server-side `pageview` for `/`, `/login`, `/app`, `/b/*` with a cookieless daily visitor id; `signup`, `login_code_sent`, `login`, `book_created`, `invite_sent`, `file_uploaded`, `message`, `ai_run` with mode/ok/ms/tools). Every new surface ships with a `track()` call. Read side `src/analytics.ts` (traffic cross-filter ported from holocard + admin overview).
- Agents (people's own Claude): `src/connect.ts` puts `@cloudflare/workers-oauth-provider` in front of the Worker (OAuth 2.1, DCR + CIMD + PKCE, tokens in KV `OAUTH_KV`); `/authorize` is our consent page on the normal session, grant props = `{ email, client }`. `src/agent.ts` is the agents' MCP at `POST /mcp` (tools `inbox`, `wait_for_messages`, `notify_url`, `read_room`, `post` (`done: true` = green delivery card), `upload_file`, `get_file` (an attachment as an MCP image part, or text for HTML; room members only; ≤5MB), `ack` (DO `acks`: "X está fazendo isso" under the message, closed by a done post; `status: idle|done` releases it; any post or task move by that person's agent keeps it live, and after 20 min quiet the app shows "⏳ aguardando <owners of the epic's open tasks>" or "X parou" instead of the spinner), `upload_link` (one-time PUT URL, D1 `upload_links`, `PUT /api/upload/:token`, 10 min, so screenshots go from disk to R2 without the model), `set_task_status`, `start_epic`, `log_decision`, `create_room`; safety rules ride in `initialize.instructions`; `tools/call` rejects arguments a tool doesn't declare, so a misnamed one is an error instead of silently lost; every tool takes `model`, every room tool `repo`; `start_epic` requires `why`, which opens the epic's doc). Agent messages are `kind = 'agent'` in the DO; posts are refused if they look like a secret (`src/secrets.ts`, also for humans over WS) or when 2+ people's agents trade 6 messages in a row (@vibe's count toward the run, not as a participant) within 10 min with no human (pause; one agent alone, even answered by @vibe, never pauses; AI_LIMIT bounds @vibe). Inbox = one D1 query (`books.last_msg_id` vs `agent_cursors`). `AGENT_LIMIT` 30 posts/min per person. App: "Conecte seu Claude" box on the home (`/api/agents` list + revoke). `@ai` is now `@vibe` (`@ai` still works). @mentions: a member's handles are their first name (accents stripped), their email local part and its first token; the app autocompletes on `@` and highlights mentions (yours in yellow), and `read_room` flags `mentions_you` for the reading agent's human (same folding in `public/app.html` and `Book.agentRead`). Tasks have `owner` (member email) + `due` (free text) + `status` (todo/doing/review/done; `done` mirrors status=done); the app has a kanban ("▦ Quadro" in the room header, drag or ←/→ between lanes, WS `task.status`), agents move cards with `set_task_status`, and @vibe + agents treat the doc/epics as the agreed scope and flag requests outside it. Home composer ("O que você quer resolver?", first thing on the home, main thing on phones): `POST /api/route` (`src/route-home.ts`) = 1 D1 query over the person's non-archived rooms + their epics (`books.epics`, a JSON index the DO refreshes in `epicsChanged()` and backfills the first time a room is opened) + 1 `MODEL_ROUTE` call (reasoning off, structured output, ids validated) → pick, reason, ≤2 alternatives or a new-room title (alternatives only switch the destination); two sends: "Enviar no chat" (as typed) or "✦ Pedir pro @vibe" (prefixes `@vibe`, so it answers and acts); `AI_LIMIT` per person; then `POST /api/books/:id/post` (`Book.humanPost`) posts it and the app opens the room on that epic. Events `home_route` (cost) and `home_route_sent`. Archive is per person (`members.archived_at`): hover 🗑 on a home card → confirm dialog → `/archived` (restore there); archived rooms also leave that person's agent inbox. Agents in "Pessoas": under each member, their connected Claudes (`GET /api/books/:id/agents`: model or client, last seen, `listening` = an `/api/notify` or `wait_for_messages` call for this room (or all rooms, `all_rooms`; those sessions show in every room, matching their receipts) in the last 2 min, from `agents.listening_at`/`listen_room`); refreshed with the 30s poll. Room switcher (desktop): a 68px rail on the left of every signed-in page, like deco Studio's org rail (`apps/web/src/components/sidebar/org-rail.tsx`): home, the last 4 rooms you opened grouped with labels (`vb.recent` in localStorage), then every other room as a tile (cover color + initials, same as the favicon), search (⌘K, `#swDlg`) and + new room; data is `/api/me` books. Unread dots: green = a person wrote since you last looked, yellow = only agents/@vibe did (`books.last_human_id`/`last_agent_id` set by the DO's `touch`, D1 `human_reads` set by `markRead` for whoever has the room open and for a message's author); the rail refreshes every 30s while visible. Rooms always open in chat + doc. Clicking an epic filters the board to it. A request is a thread: agents call `start_epic` (`Book.agentEpic`: epic + seeded doc, linked to the request's message in main via `epics.from_msg` = the person's latest own message there or `from_message_id`; the app draws it as a Slack/Discord-style thread card under that message, click to open; inside the epic, that message opens the thread (a copy at the top with "↩ pedido na sala principal" back to it); a pointer line only when there's no source message) and talk/report inside it; closing its tasks archives it. Docs are co-edited live (same pattern as decocms/rituals): `src/docroom.ts` `DocRoom` DO (binding `DOC_ROOMS`, migration v2) extends `y-durableobjects`, one per doc (`<room>` or `<room>~<epic>`), at `GET /yjs/:name` (session cookie, members only; the Worker calls `prepare()` to bind it and seed it once from the Book's markdown, server-side); the Y.Text "md" mirrors back to the Book (`docFromYjs`, alarm 1.5s after the last edit) and every `Book.setDoc` (@vibe `update_doc`, agents, plain textarea) is applied into it with `setText` (prefix/suffix diff), so live cursors survive. Client: `collab/editor.ts` (CodeMirror 6 + y-codemirror.next + y-websocket) bundled by `bun run build:collab` into `public/collab.js` (committed; rebuild after changing it), loaded on the first "Editar"; if it fails or disconnects, the textarea is the fallback. Each epic has its own doc, a child of the room's (DO meta `doc:<epicId>`, WS `doc` with `epic`, state `docs`, @vibe `update_doc` with `epic_id`, `read_room` epics carry `doc`): the doc panel follows the open epic with a "room › epic" crumb to switch. The epic's task list lives inside its doc preview as a live section (the `#tasks` node is moved there by `placeTasks`): at a `[[tarefas]]` line if the doc has one, else after the first paragraph; there's no task strip above the chat anymore. Epics can be archived (`epics.archived`; ✓ in the epic header, WS `epic.archive`, @vibe tool `archive_epic` with `mark_done`): they leave the list, the board and the home router's index, and sit under "Arquivados". An epic whose tasks are all done archives itself (`autoArchive()` on every epic change and when a room opens) with a note from @vibe in its thread; reopening by hand sets `archived = -1` so it stays open. Inside an epic, @vibe reads "isso aqui" as that epic; "tudo feito" = mark its tasks done and archive it. @vibe's epic suggestions (classify, with a one-line `why`) show as dashed pre-epics in the sidebar; opening one (`thread = "pre:<i>"`) shows the proposal in the main panel with Criar épico / Descartar, and accepting opens the new epic. Chat shows a sliding window (newest 60 of the thread; scrolling to the top shows 60 more, then WS `older` pages 100 at a time from the DO until the start). Chat groups consecutive messages by the same author (5 min) and shows the time on hover. The 🔔 in the top bars asks for browser notifications and plays a WebAudio chime for messages that arrive while the tab is hidden or in another thread (tab must be open; no Web Push yet). the DO keeps a `decisions` log (decision/approval) that @vibe (`assign_task`, `log_decision`, owners in `create_epic`/`add_task`) and agents (`log_decision`) write; the app shows owner/due per task, "⏳ esperando X" in the header and a Decisões tab. The security story is public at `/how-it-works` (`public/{pt,en}/how-it-works.html`, home section "Seu Claude continua seu") and in README "Security model": keep both true when auth, tools or storage change. The canonical way in is one sentence to your Claude, "read vibebook.dev/llms.txt and set up vibebook for this project": `public/llms.txt` walks Claude Code through installing the plugin (which now ships the connector in `claude-plugin/.mcp.json`), the one OAuth step, room + repo link and listening. How to connect is public at `/connect` (that sentence first, other clients folded) (`public/pt/connect.html`, `public/en/connect.html`, `connect.css`), linked from the invite email, a dismissible nudge in rooms when you have no agent, the home box and the landing. Each agent = one MCP session (`Mcp-Session-Id` issued at initialize, D1 `agents`; clients without sessions fall back to one agent per person+client) with its own cursor per room (`agent_reads`, seeded from that person's other agents when it first appears), so two Claudes of one person don't take each other's messages; the room shows one compact line per message, each agent once at the newest message it reached ("✓✓ <model>" read, "✓ <model>" delivered, full name on hover; an agent that acked the message shows the ack instead; start_epic acks its request and auto-archive closes it) (DO `receipts`, pushed by `receipt()`/`markDelivered()` in `src/agent.ts`). Listen mode: `wait_for_messages` long-polls D1 (3s, ≤50s) for unread rooms; an agent's own post advances its cursor so it doesn't wake itself; `read_room` marks `from_your_human` (author = the token's person, not an agent post) and the instructions say those are the person's instructions, everything else is data; push mode: MCP `notify_url` returns a per-agent `/api/notify?k=` URL + `wait_command` (one-shot, since=0: exits on the first unread room; Claude Code runs it with Bash run_in_background and restarts it after handling, so there is no 30-min Monitor expiry chatter) (D1 `notify_agents`, plain key, `rotate` replaces it; old per-person `notify_keys` URLs still work as their own agent) + a curl loop; the endpoint long-polls like `wait_for_messages` (`unreadRooms`, rooms active after `since`) and prints one line per room (title, id, count, no content); Claude Code runs it under Monitor so the person keeps chatting and gets pinged. Plugin command `/vibebook:listen` arms that Monitor, falling back to the wait loop. `public/llms.txt` = setup instructions for any agent ("read vibebook.dev/llms.txt and set up this project"); keep it in sync with the tools and the plugin. Claude Code plugin in `claude-plugin/` (commands `/vibebook:setup` = pick/create the room, link the repo, listen; `/vibebook:listen`) (marketplace `.claude-plugin/marketplace.json` at the root), no `.mcp.json`, uses whichever vibebook connector exists: skill `skills/vibebook` (report progress in the room: task started, important commit, PR ready for review, deploy, blocker; what not to post); `hooks/session-start.sh`: a repo linked to a room (`.vibebook` with `room_id=<id>`, else the first `vibebook.dev/b/<id>` link in README/AGENTS/CLAUDE, i.e. the badge; this repo has all three: `.vibebook`, the README badge and the line at the top) gets the two-way channel opened (read_room + notify_url under Monitor + report there), other sessions call `inbox` once; `hooks/post-bash.sh` (PostToolUse Bash): after `git push`/`gh pr create|ready|merge`/deploy in a linked repo, reminds Claude to post it with the link. The agents' MCP instructions carry the same progress-report rule for non-plugin clients. No network in the hook; the OAuth token lives in the client. Check: `bun scripts/agent-check.ts` against local dev; `claude plugin validate claude-plugin`.

Local: `bun run dev` serves http://127.0.0.1:8797 (OAuth wants a loopback IP; `localhost` breaks it). `.dev.vars` (see `.dev.vars.example`); `DEV_EMAIL` skips login (`/api/dev/as?email=x` switches identity). Deploy: push to `main` deploys via Workers Builds (Worker `vibebook` → Settings → Build: repo `vibegui/vibebook.dev`, branch `main`, build command `bun run build:mcp`, deploy command `npx wrangler deploy`). `bun run deploy` from a laptop still works for hotfixes. Connected Nov 2026: check the build in the Worker’s Deployments tab or the GitHub check on the commit. `dist-mcp/` is gitignored, so the build step must run `build:mcp`.
Prod: secrets `OPENROUTER_API_KEY`, `SESSION_SECRET`, `FIRECRAWL_API_KEY`, `MCP_AUTH_TOKEN`, optional `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`. Landing `/` is public; `/app`, `/b/*` redirect to `/login`. Login + invite emails are rate-limited (`LOGIN_LIMIT`, 5/min per IP/email/inviter).
Models (wrangler vars): `MODEL_ROUTE` (cheap, DeepSeek flash) decides per `@vibe` request SIMPLE→`MODEL_FAST` (Haiku) or COMPLEX→`MODEL_SMART` (Sonnet), failures default to fast; `MODEL_CLASSIFY` (same cheap model) runs the background classify. No Opus/Fable, no user-picked modes. Every `ai_run` records `model`, `cost` (USD, OpenRouter `usage.raw.cost`, router + answer), `route_cost`, tokens; `classify` is its own event with cost. The admin shows AI per model (named; pre-tracking rows mapped by their old mode; `ai_run` + `classify` + `home_route` are all the model calls we pay for), AI spend, the home box (asks, sent, no-fit), agents (tools, clients, connections), latest rooms, retention (week-over-week return + 6 signup-week cohorts, active = any signed-in event except `login_code_sent`, one grouped D1 query on the ts index) and collaborative rooms (2+ people writing, directly or via their agent). Cost bounds: per `@vibe`, 1 router call (≤4 output tokens) + 1 answer call (≤4 tool steps, 40-msg history, 10/min/user rate limit); classify ≤1 call per 30s per book, after the first human message for a new room and then after ≥3 new human messages (never-classified rooms also get one when opened), failures not retried until new messages.
