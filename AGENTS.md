# vibebook

Shared AI docs with friends: each vibebook = doc + group chat + epics/tasks, with `@ai` in three modes.

- `src/index.ts` — Hono Worker: own auth (`src/auth.ts`: email 6-digit code via Cloudflare Email Sending + optional Google OAuth, HMAC session cookie), D1 index (users, books, members, friends), serves `/app` + `/b/*` shell, forwards `/ws/:id` to the book's DO.
- `src/book.ts` — `Book` Durable Object (SQLite): messages per thread (`main` or epic id), epics, tasks, doc; WebSocket hibernation; `@ai` via OpenRouter with tools; debounced alarm classifies (title/folder/summary/epic suggestions) with `MODEL_CLASSIFY`.
- Files: `POST/GET /api/books/:id/files[/:fid]` → R2 `FILES` (`<book>/<file>`), png/jpeg/webp/gif/pdf ≤10MB (no SVG/HTML), served with nosniff + CSP sandbox, `UPLOAD_LIMIT` 30/min. The DO keeps the file index + message attachments; the newest ≤4 images in the thread are sent to the model as image parts.
- Polls: DO tables `polls`/`votes`, WS `poll.create`/`vote`/`poll.close`, AI tool `create_poll`; results are in the AI context.
- `src/reader.ts` — `read_url` AI tool: URL guard (public http(s) only), Firecrawl scrape (`FIRECRAWL_API_KEY`), cleaned + capped at 20k chars, handed to the model as untrusted data. ≤4 reads per `@ai`, `READ_LIMIT` 20/min per user, cached in the DO 6h (failures 10min). Check: `bun scripts/reader-check.ts`.
- Analytics: `src/track.ts` writes first-party events to D1 `events` (server-side `pageview` for `/`, `/login`, `/app`, `/b/*` with a cookieless daily visitor id; `signup`, `login_code_sent`, `login`, `book_created`, `invite_sent`, `file_uploaded`, `message`, `ai_run` with mode/ok/ms/tools). Every new surface ships with a `track()` call. Read side `src/analytics.ts` (traffic cross-filter ported from holocard + admin overview).
- Agents (people's own Claude): `src/connect.ts` puts `@cloudflare/workers-oauth-provider` in front of the Worker (OAuth 2.1, DCR + CIMD + PKCE, tokens in KV `OAUTH_KV`); `/authorize` is our consent page on the normal session, grant props = `{ email, client }`. `src/agent.ts` is the agents' MCP at `POST /mcp` (tools `inbox`, `read_room`, `post`, `set_task_status`, `log_decision`, `create_room`; safety rules ride in `initialize.instructions`). Agent messages are `kind = 'agent'` in the DO; posts are refused if they look like a secret (`src/secrets.ts`, also for humans over WS) or after 6 agent/@vibe messages in a row with no human (pause). Inbox = one D1 query (`books.last_msg_id` vs `agent_cursors`). `AGENT_LIMIT` 30 posts/min per person. App: "Conecte seu Claude" box on the home (`/api/agents` list + revoke). `@ai` is now `@vibe` (`@ai` still works). @mentions: a member's handles are their first name (accents stripped), their email local part and its first token; the app autocompletes on `@` and highlights mentions (yours in yellow), and `read_room` flags `mentions_you` for the reading agent's human (same folding in `public/app.html` and `Book.agentRead`). Tasks have `owner` (member email) + `due` (free text) + `status` (todo/doing/review/done; `done` mirrors status=done); the app has a kanban ("▦ Quadro" in the room header, drag or ←/→ between lanes, WS `task.status`), agents move cards with `set_task_status`, and @vibe + agents treat the doc/epics as the agreed scope and flag requests outside it. Chat groups consecutive messages by the same author (5 min) and shows the time on hover. The 🔔 in the top bars asks for browser notifications and plays a WebAudio chime for messages that arrive while the tab is hidden or in another thread (tab must be open; no Web Push yet). the DO keeps a `decisions` log (decision/approval) that @vibe (`assign_task`, `log_decision`, owners in `create_epic`/`add_task`) and agents (`log_decision`) write; the app shows owner/due per task, "⏳ esperando X" in the header and a Decisões tab. The security story is public at `/how-it-works` (`public/{pt,en}/how-it-works.html`, home section "Seu Claude continua seu") and in README "Security model": keep both true when auth, tools or storage change. How to connect is public at `/connect` (`public/pt/connect.html`, `public/en/connect.html`, `connect.css`), linked from the invite email, a dismissible nudge in rooms when you have no agent, the home box and the landing. Claude Code plugin in `claude-plugin/` (marketplace `.claude-plugin/marketplace.json` at the root): hook only (no `.mcp.json`): a SessionStart hook tells Claude to call `inbox` once per session through whichever vibebook connector exists (claude.ai connector, `claude mcp add`, …). No network in the hook; the OAuth token lives in the client. Check: `bun scripts/agent-check.ts` against local dev; `claude plugin validate claude-plugin`.
- Admin MCP: `POST /mcp` (JSON-RPC, `Authorization: Bearer MCP_AUTH_TOKEN`), tools `admin_overview` / `traffic_overview`, each with an MCP-App UI (`ui://vibebook/admin|traffic`). UI source `mcp-app/` (vanilla TS + `@modelcontextprotocol/ext-apps`), bundled by `bun run build:mcp` into `dist-mcp/index.html` (gitignored, imported as text). `bun run dev`/`deploy` build it first.
- Landing + demo in pt and en: `public/pt.html`, `public/en.html` (shared `landing.css`), `public/pt/demo.html`, `public/en/demo.html` (shared `demo.css` + `demo.js`, a scripted replay with both scripts, picked by `<html lang>`; no network). `/` and `/demo` 302 to `/pt` or `/en` by `vb_lang` cookie, else Accept-Language (pt default); opening `/pt`/`/en` sets the cookie. Edit copy in both languages.
- `public/app.html` app (vanilla JS, no build), `og/og.html` renders `public/og.png` and, with `?lang=en`, `public/og-en.png` (headless Chrome, 1200×630).

Local: `bun run dev` serves http://127.0.0.1:8797 (OAuth wants a loopback IP; `localhost` breaks it). `.dev.vars` (see `.dev.vars.example`); `DEV_EMAIL` skips login (`/api/dev/as?email=x` switches identity). Run with `--var DEV_EMAIL:` to test real login; sent emails land in `.wrangler/tmp/email/`. `bun run dev`, `bun run check`.
Prod: secrets `OPENROUTER_API_KEY`, `SESSION_SECRET`, `FIRECRAWL_API_KEY`, `MCP_AUTH_TOKEN`, optional `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`. Landing `/` is public; `/app`, `/b/*` redirect to `/login`. Login + invite emails are rate-limited (`LOGIN_LIMIT`, 5/min per IP/email/inviter).
Cost bounds: 1 OpenRouter call per `@ai` (≤4 tool steps, 40-msg history, 10/min/user rate limit); classify ≤1 call per 30s per book, only after ≥3 new human messages, failures not retried until new messages.
