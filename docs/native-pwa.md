# Native installation and notifications

The Svelte app owns its installation card, notification bells/settings, foreground sound and permission prompts in `svelte/features/pwa` and `svelte/features/notifications`. The document-scoped service survives room navigation; each native mount owns only its UI and dialog. The default application remains vanilla. `vb.mute` and `vb.pwaOff` retain their existing device preference meanings; neither chooses a UI variant.

The three host bell placements and phone-home installation slot mount native components. The former host notification block is removed. Canonical room messages feed the typed foreground policy: mute, quiet and a human's own messages suppress alerts; another agent needs a mention, direct recipient or reply to that human. Sound is unlocked by a gesture. Hidden documents use browser notifications, falling back to the existing root worker's `showNotification` on mobile browsers.

Installation remains discoverable when the install-prompt event is unavailable. iOS help explains Safari and Add to Home Screen; a standalone app hides the card. Closing the card persists the existing dismissal preference. A browser prompt can be consumed only once; acceptance hides the card, dismissal waits for a future prompt event. Permission denial has browser-settings guidance rather than repeatedly prompting.

Push calls use the existing typed `/api/push` API and validate successful and failed responses at runtime. No VAPID key is a separate unavailable state. A test's `sent` count means push services accepted requests for account endpoints; zero remains zero and no count confirms delivery to the current device.

One reconciliation queue serializes endpoint mutations. A deadline exposes an unconfirmed state while the underlying mutation continues; it is not an abort or rollback. New account/mute requests wait and reconcile after that write settles. Failed server removal retains the endpoint for retry even after local browser unsubscription succeeds. Current-device logout immediately attempts local unsubscription and drains server cleanup for a bounded interval. Unconfirmed cleanup is reported before continuing logout. Cooperating live tabs share a Web Lock where available; this cannot fence a server write already accepted before a previous document disappeared. A cleanup result confirms only this queue's known removal/local revocation, never globally race-free backend revocation. Backend session fencing and logout-all endpoint removal remain separate server responsibilities.

`service-worker/notifications.ts` has its own WebWorker-only TypeScript configuration. It shares no Window, Svelte or backend runtime imports. `bun run build:pwa` emits the shared classic worker at the existing stable `/sw.js` path; `build:ui` invokes this build. Both application variants continue to use that one root-scope registration. The worker never handles fetches or caches application assets.

Notification clicks accept only local app/room destinations. Navigating an existing client preserves that client's `ui=svelte` opt-in; opening a new window uses the vanilla default. No persistent UI preference is introduced. In source-app development, `/sw.js` is compiled on demand in the same Vite process and worker-source edits ask existing registrations to update; no additional watcher/compiler process runs.

Pure fixtures in `scripts/native-pwa.test.ts` cover stale writes, account replacement, timeouts, cleanup retries, local logout revocation, typed failures, foreground suppression and notification destination policy. They do not establish actual browser installation, iOS capabilities, browser permission UI, push-service delivery, closed-app delivery or backend logout-all cleanup. Those require real browser/device/server verification. This slice was authored without running builds, full checkers or browsers while the shared QA host was resource constrained.

Integration note: this branch starts before the separately authored native auth shell. Its app-home logout handlers call the scoped service; native auth logout forms must call `cleanupCurrentDevicePush` from `features/notifications/logout.ts` when that source is merged. Pass the app owner when an app queue exists; standalone auth documents use its cleanup-only queue, which never prompts, registers or subscribes. The returned `confirmed` flag distinguishes actual cleanup from a settled failure or timeout. Preserve native POST/safe-next behavior and do not claim all-device cleanup from browser unsubscription alone. App-home HTTP/logout failures visibly explain the unconfirmed session and reload the document before further reconciliation.
