# Application personal channel source checkpoint

`createApplicationPersonalChannel` owns the document's existing `/ws-me` connection and the room-bound 600 ms agent refresh previously held by `connectMe` and `agentsRefreshTimer` in the legacy host. It consumes the existing PersonalSession and AgentsService; it creates no second account cache, authorization policy, PWA owner, room connection or metadata endpoint.

The temporary host adapter projects PersonalSession's email/revision, current routed room and immutable Book connection identity. Account or revision changes synchronously dispose the old channel and its pending room refresh; a replacement channel starts after a non-null account observation. Connected refresh still invalidates/reads Me and personal grants, refreshes the Agents account, and refreshes the matching live room. Visibility refresh preserves its existing distinct behavior (Me, grants and matching room). The lower connection owner retains typed notice decoding, current-room message suppression, reconnect backoff and visibility listeners.

Every callback captures its account/connection generation. The room timer also captures route generation and exact Book connection identity, with a separate timer revision that fences callbacks already queued before cancellation. Route activation and router before-change cancel only that room timer; account-channel ownership survives ordinary navigation. Identity replacement and document/HMR disposal remove connection resources and the identity subscription. Existing feature/session owners continue to guard their own asynchronous HTTP results.

Eight focused source tests cover start/single ownership, connected versus visible refresh parity, account and agent observations, matching-room debounce, stale queued timers, route/Book replacement, identity/revision restart, synchronous reset before queued identity subscribers, reentrant identity change and disposal. The source fixture is registered in the connection gate and tooling scope. No formatter, test, type checker, build, Worker or browser has run for this checkpoint; public assets are unchanged. RootApp/AppServices may adopt this typed coordinator directly in the subsequent shell migration.
