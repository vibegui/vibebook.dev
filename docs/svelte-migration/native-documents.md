# Native room and epic documents

The native document mount owns preview/editor mode, room/epic breadcrumb, review notes, Edit/Done controls, shared panel tabs and the phone document toolbar. The host's document HTML/Markdown/Pele builders, textarea timer, collab globals, legacy stylesheet selectors and moved-task-DOM implementation are retired in this branch. Native Tasks render at a semantic document slot rather than moving a live node through an HTML replacement. The remaining host `renderDoc`/`renderPeek` functions only update typed native mounts and bridge existing room navigation. Chat heading/archive/delete actions remain their existing independent owner.

`DocumentSession` binds every target to account, room and optional epic, including missing-doc requests and delayed fallback writes. It rejects old import/provider/timer callbacks after target/account disposal. A component-owned one-entry rich-text cache avoids reparsing unchanged previews on receipt/presence refreshes. Task component identity survives ordinary room updates and Read/Edit mode switches. A typed local draft bag preserves unconfirmed edits for explicit review and replacement rather than automatically writing an older document into a new target. Identity replacement clears this bag after disposing the old owner. Selection and scroll are scoped to target and restored once per new editor after synchronization.

The browser-only editor adapter loads on demand through the native Vite graph. The existing vanilla `collab/editor.ts` and stable vanilla assets are unchanged. A single active Y.Doc (`md`) and CodeMirror view survive transient disconnection; the interface reports connection/initial-sync state without claiming durable server storage. A textarea is available only when the editor module or initial mount fails. Missing document reads and whole-text fallback writes use the existing scoped Promise command API, with separate bounded canonical waits and explicit retry. That fallback retains its draft and reports unconfirmed writes until an actual canonical value matches; an ACK is not durable CRDT storage. Removed-epic edits remain available as read-only orphan review/copy/discard; they are never retargeted or replayed. Backend rejection or disconnect never authorizes switching to a competing whole-text writer while a CRDT is active.

Remote awareness is untrusted. Both local and remote labels/colors and relative cursor positions are normalized before `y-codemirror.next` builds decorations; peer-provided CSS strings never become appearance input. The adapter disables y-websocket BroadcastChannel synchronization so a different account or removed member cannot bypass a new Worker authorization check through a same-origin peer. CodeMirror and y-codemirror structural editor/selection CSS remain only the existing named vendor exceptions; first-party typography, cursor, selection surface and toolbar appearance use Tailwind/Studio utilities. This source contains no first-party `EditorView.theme` objects or new CSS family.

No server/Yjs protocol changes are introduced. `/yjs/:room[~epic]` continues to authenticate cookies and Origin, check membership and the actual document seed, then relay the existing y-websocket binary protocol to DocRoom. DocRoom owns the live CRDT; Book receives its delayed mirror after 1.5 seconds and still caps the mirror at 100,000 characters. Agent/whole-text updates continue flowing back through DocRoom.setText. Existing `doc.get`, content/invalidation events, >8 KiB epic invalidations, server task synchronization and membership kick behavior remain compatible with vanilla. Backend source modules never enter the browser graph.

The neutral rich-text layer exposes closed policies: default chat retains its 64 KiB rendering budget and forbids images; `document` permits safe HTTP(S)/relative images and a 100,000-character source budget; `file-preview` retains the vanilla file viewer's image prohibition and supports its 300,000-character preview budget. Image attributes are generated from validated source/alt/title only, with no-referrer, lazy loading and no raw control hooks. Images with credentials, executable/data schemes or untrusted style/event attributes are refused. Document and file relative URLs use the explicit current room-page base, matching the old rendered-page behavior. Complexity limits preserve the full original source as visible literal text rather than truncating it. These policies do not relax chat.

Mermaid retains the pinned Pele 1.10.0 CDN/SRI loader with links/images disabled. Renderer output is treated as untrusted: bounded SVG goes through the existing inert AST projection, private IDs and reference mapping, then a diagram-only pass removes active nodes, image/link resources and authored paint/typography. Native SVG nodes and Tailwind utilities render the result; no HTML insertion, style element, DOMParser or additional stylesheet is used. Both editor-module and pinned renderer loading have owned 30-second deadlines; a timed-out old attempt cannot settle a retry. Renderer failure keeps its source visible. Real diagrams, visual parity and offline/CDN failure behavior remain runtime gates; F31 is not declared complete from source fixtures.

Explicit shell debt remains: the room's outer `.doc` pane container, phone drag/Back/Escape adapter, sheet dim/handle, viewport measurements and desktop width resizer still belong to the transitional host. Typed tab callbacks do not give those adapters an HTML or CSS exception. Their final retirement remains part of the complete migration; this slice does not claim the full native room shell or F50 complete. The Viewer and Composer maintain separate owners and are not reimplemented here.

Focused fixtures cover exact targets, remote-awareness normalization, document/file/chat policies and budgets, task placement, SVG sanitation, deferred A→B→A editor imports, disposal, one-editor reconnect, stale fallback writes and unknown confirmation. They do not replace real transport/browser gates. Root must still run strict frontend/tooling checks, native style audit, production builds/boundary gates, DOM/keyboard/mobile checks and a real Worker test with two vanilla/native Yjs editors, concurrent Unicode edits/undo, reconnect, agent updates, room/epic switching, >8 KiB invalidation, permission removal, Viewer file targets, task placement and HMR. Production/deployed compatibility is separate acceptance.

Meaningful adversarial single-line and ordinary large fenced-source fixtures remain. Subsequent measurements and runtime rendering remain separate gates.

A Yjs permission close latches a room/account denial associated with the current Book connection epoch. Queued state/members frames from that old epoch cannot clear the gate. The explicit access-check control opens a new authenticated Book connection without rendering its cached room; only a newer real authorization epoch can unlock it. Canonical document preview/editor/task DOM is removed while denied; only explicit local retained text remains available for guarded copy/discard.

Backend dependency: at the inventoried base, Book’s fallback `doc` command treats a supplied deleted/unknown epic as the room document. Client target checks cannot prevent an epic deletion racing a command already sent. The separately owned authoritative server fix must refuse that supplied unknown epic before claiming the fallback race closed; absent epic must retain its room-document meaning. No backend behavior is changed by this source slice.
