# Native room Inbox parity

The shared account-owned Inbox owner now selects presentation by captured scope: an authorized room uses the in-place Inbox, and Home retains the existing dialog. Home has an explicit Inbox trigger. Opening a room Inbox keeps the URL/thread, chat/composer/document/Board owners and DOM instances; their outgoing surfaces are hidden and inert. Closing restores the current draft and reading anchor, and restores a still-visible connected opening trigger without stealing newer focus.

The message column preserves oldest-first message waits, Claude waits and mentions, with mention/wait message deduplication, date separators and exact canonical navigation. The document column separates task waits from the remaining own tasks, groups tasks by room/epic and preserves current-room/all tabs. Only m-waits offer the existing HTTP resolve action; clicking a task does not change its status. Unchanged HTTP rows preserve object identity, while replaced rows and connected controls from older openings cannot acquire a new target.

Room membership/terminal departure synchronously clears private Inbox rows and revokes old controls. Personal remains the sole canonical wait owner: a newer Personal update wins over an older Inbox HTTP response. Read/write deadlines, known global401 revocation and the existing close/publication/navigation reentrancy fences remain in place. No Inbox payload is persisted.

RoomLayout owns the additional document-width binding through its existing CSS animation and width state. The original document/Board cells retain their animations while invisible beneath the overlay; the single Board is neither moved nor remounted. There is no independent width store, first-party inline style or new stylesheet.
