# Native design system migration

The owned component layer is `svelte/lib/ui/`, with reusable compositions in `svelte/lib/components/`. Its source follows the shadcn-svelte model: application-owned typed Svelte components, Tailwind classes and headless Bits UI interaction behavior. Primitives do not import application stores, authentication or backend services.

The current catalog includes Button/IconButton, Icon, Input/Textarea, Label, Checkbox, Switch, RadioGroup, Select, Badge, Avatar, Separator, Skeleton, Progress, Tooltip, Tabs, Dialog/Sheet, Card, Field, EmptyState, ErrorState and LoadingState. Native Inbox and task controls compose this same layer. The interactive gallery is at `/app?ui=svelte&gallery=1`.

The typed bootstrap selects the native gallery independently of the legacy application host. `legacy/host.d.ts` declares only that existing side-effect entry and exposes no application API; the JavaScript implementation and this temporary declaration remain explicit M6 debt. `dev:components` serves the gallery through Vite HMR at `http://127.0.0.1:5173`; full-application/Worker HMR and shared-contract edit verification remain M7 work.

The temporary Inbox mount uses a typed readable store so profile/wait updates refresh an open dialog without replacing its instance. Closing/navigation invalidates pending opens, and a completed resolve never opens a dialog. It removes the matching room/ref and updates active data. This mount bridge retires with the remaining host.

The task panel now uses native atoms and Tailwind for its count/progress, title editing, owner selection, due-date form, deletion and new-task form. The progress element owns its native fill geometry; no dynamic width style is authored. False/throwing sends retain drafts, and Select can reject a proposed value without changing the committed selection. Due dates use a typed Dialog/Field/Input flow instead of a browser prompt.

Dialog registration allows synchronous teardown before routing, history changes or opening the remaining native switcher. Optional initial focus targets the form input. The legacy mobile sheet's Escape handler recognizes the Svelte modal marker and prevented events, so dismissing the top modal keeps its document sheet open. These host adapters remain migration debt until the native shell replaces them.

`svelte/styles.ts` imports the sole new stylesheet, `svelte/styles/tailwind.css`. The application bootstrap loads it once; the lazy gallery receives those same styles and must not import the bootstrap. Vite compiles Tailwind, emits one `ui.css` asset and disables Svelte component CSS injection for preview builds. Build/version checks include the emitted CSS and reject reverse imports of the versioned bootstrap, which would execute it twice under distinct module URLs.

Utilities use Tailwind's `tw:` prefix. This prevents generated utilities such as `.table` from overriding legacy preview classes during the migration. Class merging understands that prefix and the semantic radius/shadow aliases. New source uses complete prefixed literals; there is no runtime prefix concatenation.

`components.json` points source generation at the same stylesheet, frontend TypeScript project and `$lib` aliases. Its required `baseColor` field is generator metadata; the installed palette is the frozen Studio mapping. Generated components become owned source: adapt their classes to the configured `tw:` namespace, retain the Studio tokens and apply the source/style/accessibility checks. Do not initialize a second stylesheet or replace the existing theme with a generator palette.

Semantic values come from the frozen Studio reference and are namespaced `--vb-*` during the transition so they cannot recolor the remaining legacy features accidentally. All new presentation uses complete Tailwind utility classes and typed variants. Input accepts text-like types; numeric/file controls require their own correctly typed adapters. Native avatars preserve profile images and fall back to initials on neutral Studio surfaces, an intentional visual change from the old arbitrary avatar colors.

Form controls retain native input semantics, including form submission and keyboard behavior; Bits UI supplies dialog focus trapping, Escape/restoration, tabs and tooltip positioning. Application appearance and modal scroll locking come from Tailwind; Bits UI body-style mutations are disabled. The vendor manifest names exact dependency versions and files for genuinely required positioning/editor internals. It does not permit first-party CodeMirror theme objects or legacy overrides.

Contrast verification found that red status text on tinted surfaces and the dark destructive fill/label pair were unsuitable for small text. The palette values remain unchanged: status labels and validation text use Studio foreground roles, destructive actions use the card/foreground pair with a destructive border/hover accent, and error descriptions use foreground on their tinted surface. Color is supported by explicit text and invalid-state semantics.

## Verification and remaining work

- `check:styles:native` audits the migrated sources using Svelte/TypeScript/CSS syntax trees, exercises prohibited-style fixtures, inspects the emitted CSS count and checks font/notice integrity and vendor versions. It explicitly reports its incremental scope.
- `check:styles` audits the full application and currently fails on remaining legacy presentation. It must pass without incremental scope before M3 or final acceptance can close. The temporary `legacy` CSS layer remains a migration debt, not a policy exception; the native Inbox's old rules have been deleted.
- `test:design-system` runs against a local Worker and actual built assets: loaded fonts, form controls, keyboard tabs, dialogs, focus/scroll cleanup, responsive sheets, light/dark/mobile axe and the real Inbox. It isolates legacy-only Google font CSS but loads/verifies the native local WOFF2 files. It is not authenticated production or complete feature-parity evidence.
- `capture:studio` reproduces the frozen source reference. Workspace screenshots/computed-role comparisons, final font-transfer budgets and all-screen theme consistency remain required.

The local production-bundle browser run passed the complete Gallery and Inbox scope. It compared all 134 source tokens (92 colors plus typography, dimensions, shadows and easing) and nine rendered roles in light/dark at DPR 1 and 2, with zero mismatches. The DPR 2 check covers Studio's half-pixel hairline override. Gallery light/dark/mobile and Inbox mobile axe reports have zero violations. Inbox checks include closing/reopening during a held resolve, retained data and retry after HTTP 500, focus/Escape handoff to the native switcher, and following a real cross-room message link with `ui=svelte` preserved. The fixture isolates legacy Google CSS and supplies an empty local runner; it does not verify either integration.

A real Vite browser check also verified child Button and stylesheet hot updates: a filled gallery field survived, no full navigation occurred and both source files were restored byte-for-byte. To reproduce the component case, fill Room name, temporarily add a `data-hmr-proof` attribute to `Button.svelte`, verify its appearance without navigation/draft loss, then restore it. For stylesheet HMR, temporarily change the light `--vb-background` token and verify the rendered background changes and restores without navigation. This evidence covers only the gallery; full-app, backend and shared-contract HMR remain pending.

Menus/popovers, AlertDialog, command/search, toast orchestration, tables/lists and pagination/history compositions must be added and used as their domain features migrate. Existing feature panels and the JavaScript host still need their native Tailwind replacements. A gallery of available primitives does not complete M5 or M6; each feature's actions, remote updates and errors still need evidence in the parity matrix.

`test:tasks` exercises real UI commands and backend persistence, modal focus/Escape/native-switcher handoff, 1440/768/390px theme/accessibility checks and real browser-side WebSocket closure/recovery. Its unfinished control task intentionally prevents the existing auto-archive rule from interrupting completion-toggle verification. A queued WebSocket send is not a server acknowledgment: production/multiple-client acceptance and the remaining protocol/error coverage still require the full plan's gates.
