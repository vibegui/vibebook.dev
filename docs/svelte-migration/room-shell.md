# Direct native RoomShell source

RoomShell accepts the application room presentation and the account-owned RoomResources bank. It reads the actual RootRoom snapshot: loading, removed and unavailable states have native status UI, and an authorized snapshot creates one scene keyed by room/account/identity/connection generation. No fake room state, disabled feature stub, HTML formatter or mount registry is supplied.

RoomScene composes the existing typed native Sidebar, ThreadHeader, Chat, Composer, Document/Toolbar/Peek, Board, Files, Apps, Agents, Decisions, Reminders, Viewer, ThreadFiles and SuggestionPreview directly. RoomScope owns projections and feature lifetimes; RoomLayout owns geometry, grab handles and history. The Sidebar's legacy handle is suppressed in the direct layout. Agent attention stays outside the message scroller and outside the shared header row. The Board mounts on first use and then stays at one DOM location while CSS grid placement changes between document pane and full board. AgentsPane retains its existing selected-pane mount lifetime. Other pane surfaces retain their room-owned state while hidden. Composer is hidden in full board and absent for pre-suggestions as projected by the native owner.

Header controls preserve Home, full Board, task count, global Inbox/count/stuck indicator, PWA bell, agent trigger and document toggle. The original feature projections retain exact attachment IDs/versions, asks/replies/receipts, rich content/actions, document tasks/editor/recovery, pin ordering, permissions, connected apps, sandboxes/terminal and deletion handling. Existing native components remain the presentation owners; RoomShell does not reproduce their business rules.

The source harness mounts the actual RoomShell, Layout and Scope owners with controlled canonical Book frames. Cases cover genuine loading/removed states, direct native canonical content, retained Board DOM identity across placements, and still-connected outgoing Composer controls after access removal. This is component-level capability evidence when run, not real Worker/browser/layout/provider proof.

Dependencies are the original ApplicationServices/account-reset followups, RootApp resources, native RoomScope and RoomLayout modules. Bootstrap remains unchanged until the root integrates these coherent modules. Source fixtures, formatter, types, style, build, browser and performance gates are UNRUN under the resource hold. No full M6 or full-plan completion claim is made.
