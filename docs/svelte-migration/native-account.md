# Native account, profile and local device lock

The opt-in Svelte host mounts a native Account dialog from Home, Archived and room settings. It owns name/avatar forms, friends, sign-in history, archive navigation, theme, language, notification control, current-device logout and logout-all confirmation. Vanilla stays the default. Account sign-in history describes methods already used and available providers; it does not link identities or turn a different provider email into the same account.

`createAccountApi` uses the inferred existing Hono routes and shared runtime response schemas. The backend remains authoritative for authentication, CSRF, sanitization, email validation, upload size/type/rate and mutations. Avatar conversion preserves the existing center-cropped 256px JPEG contract. Every awaited conversion rechecks the same live Account operation before uploading. Stored private data and callbacks are fenced synchronously by Personal identity revision, account and open generation. Closing a dialog disposes its asynchronous effects; same-account name/email drafts remain available on reopening. An account replacement clears them.

A successful mutation response does not invent a new `/api/me` snapshot. The session asks Personal for one fresh read, waits at most ten seconds for the desired canonical state, then reports an unconfirmed change with explicit Refresh/review. An ignored-abort request is bounded at twenty seconds, cannot submit a late converted avatar, and requires explicit review before another mutation. No automatic mutation retry is performed. Known client/auth/rate refusals remain explicit errors. Logins have a separately owned cancellable read, deadline and retry.

The actual host logout helper is single-flight and preserves the existing single PWA service, cleanup warning, real POST endpoints, failed-response reload and success navigation. It refuses a POST when Personal has observed a different account or identity revision during cleanup, and reloads the frozen document instead. This guard only observes this document's account state: it cannot make a server cookie change atomic with an HTTP request, fence dead-document writes, or establish an all-device guarantee beyond the backend's existing semantics. Standalone native auth logout remains separately implemented by AuthLogoutForm and its cleanup helper.

The local device lock remains a display lock using `vb.lock`, not server authentication. The document owns exactly one native full-screen lock and visibility listener, with disposal on HMR. It appears initially for an existing local credential or after more than five minutes hidden. Credential creation and assertion begin only from the respective user gesture; cancellation, missing capabilities, unavailable storage, bounded sixty-second requests and late identity/disposal results are explicit. No credential ID or challenge is sent to the server. The locked screen traps focus, ignores Escape/outside dismissal, and unlocks only after a non-null public-key credential. This preserves the existing device-local mechanism rather than claiming cryptographic server-side session protection.

Personal AgentSettings is a separately owned feature. Account exposes `mountAgentSettings(node): () => void`; the Agents author supplies the native `agentSettings` registry component and `AgentAccountSession` owner. While that source dependency is being integrated, the source checkpoint still has a clearly marked temporary legacy setup/agent mount. Do not claim complete account/agent legacy retirement until the native callback replaces it. The Account dialog itself has no raw HTML or icon bridge. It uses shared Tailwind atoms and the same PWA owner.

## Verification

- `scripts/native-account.test.ts`: pure owner and actual HTTP-client validation fixtures, including delayed ACK/canonical reversal, ignored abort, account replacement, stale avatar conversion, local lock prompts/deadlines and actual logout helper behavior. These are not real DO or hardware tests.
- Native Account cases in `scripts/ui-panels.test.ts`: real components/forms, retained uncertainty draft, detached submit, synchronous private cleanup and unsupported-device labeling. Happy DOM cannot prove geometry or WebAuthn delivery.
- `scripts/native-account-browser.ts`: requires an already running loopback DEV_EMAIL Worker, creates/removes a synthetic friend, saves/restores the account's name, reads actual canonical `/api/me`, and uses a browser CDP virtual authenticator to exercise actual WebAuthn creation/reload/unlock/disable gestures. No canonical state is fabricated. The loaded `vb-v` and supplied asset revision are recorded. It does not prove hardware Face ID, OS suspension, production cookies or all-device logout. Failure artifacts belong to the dedicated development test account.
