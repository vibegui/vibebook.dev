# Optional CPU and initial heap diagnostics

`METRICS_DIAGNOSTICS=1` adds one clearly marked extra trial for each configured workload, device and variant after the original matrix, report and budget calculation. These trials reuse the controlled fixture, actions, 4× CPU throttle and readiness endpoints. They are appended only to `diagnostics.trials`, never the measured `samples`, summaries, byte summaries or budget assessment. Existing warmups, seven measured repetitions, thresholds and failed/unverified acceptance remain unchanged. With the flag absent the extra trials do not run.

CPU sampling covers entry navigation through canonical visible-document/chat readiness, fonts and two frames; it stops before the initial post-GC heap snapshot. A second profile covers the existing thread-switch action/readiness interval. Profiles contain numeric sampled self-time/counts, function/line/column only for verified CDP script IDs without sourceURL/eval/live-edit provenance, whose exact observed asset URLs and CDP content hash match the served SHA-256 (with original SHA-256 also recorded), and asset keys instead of URLs/query strings. Unmatched/eval/external/inline/hash-mismatched frames have generic names and no URL or position. Matched and unattributed sample counts are reported explicitly; no coverage is presumed before the actual browser run. This is sampled CPU self time, not allocation of compressed chunk bytes or hardware latency.

The initial heap snapshot is streamed as UTF16LE into a mode0600 temporary file in a private temporary directory outside the artifact tree. UTF16LE preserves surrogate halves split between CDP chunks. The file is capped at 128MiB before bounded JSON parsing; overflow or malformed data makes that diagnostic unavailable, never zero or accepted. Exported data contains only allowlisted node types with counts/self sizes and numeric string-length buckets; class/object names, string contents, edges and object IDs are not exported. Raw snapshot files and directories are always deleted, including failures; there is no retention option.

Diagnostic profiling, GC and snapshotting perturb these extra trials. They are not substituted for any measured latency, font/JS byte or heap budget, and cannot establish absence of leaks or Worker/provider/editor lifecycle acceptance. Normal benchmark reports retain their original execution and acceptance state. Instrumentation/cleanup failures are reported separately and do not turn a failed budget into a pass. Raw snapshots must never be added to CI artifact paths.

Source tests cover numeric summaries/private-content exclusion, malformed snapshots/profiles, split astral UTF16 round trips, exact observed-asset CPU attribution and actual private-file cleanup on success, cap, parse, transport and unsafe-directory failures. Author Node formatter passed the six owned paths and the final four-file followup. Five focused tests passed 52 assertions in 861ms after script-provenance hardening. Types/browser/actual diagnostic cohort remain UNRUN; no local Vite/compiler/browser was launched.
