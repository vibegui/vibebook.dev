# Native interactive message bodies

The real Message mount renders cards, choices, permission asks and polls through typed native Svelte components. `LegacyChatIntegrations.interactiveBody` and its host HTML builders and delegated mutation handlers are removed. `threadCards` is the remaining named HTML fragment. RichContent continues to render surrounding message Markdown; card strings remain literal plain text, matching the existing catalog rather than interpreting agent labels as Markdown.

`shared/card.ts` owns the pure existing card normalizer and a schema-derived normalized DTO. The backend's `src/card.ts` re-exports that contract. The wire remains a nullable JSON string in Message. Existing normalization/coercions/unknown-prop removal and historical Text.text/Table.columns/Chart.chartType/Image.src aliases are preserved. A golden fixture generated from the previous backend normalizer checks serialized output for all 12 catalog types. Invalid cards are caught per message body and leave ordinary message text/other valid surfaces available.

A shared inline rendering-cost budget keeps dense valid tables/charts available behind native fullscreen openers rather than eagerly materializing every cell/bar. One expanded surface per card renders all of its bounded catalog data; no accepted catalog field or row is removed. Oversized raw card sources retain visible escaped JSON access.

The catalog preserves Card/Section/Text styles/Fields/Field/Table/Chart bar and line/Divider/Image/Actions/Button/LinkButton. Tables retain keyboard-accessible fullscreen expansion through the shared Dialog; chart bars use native progress and lines use finite SVG coordinates. Images remain same-room uploaded files. LinkButtons retain external HTTP(S), message, thread, document and room/connection app destinations through scoped typed callbacks. Duplicate card elements/deep graphs, unknown components and existing normalizer limits remain refused.

Only an open agent prompt's own human may send card/permission answers. The first canonical own human reply determines answered state; someone else's reply cannot settle the prompt. Choices preserve radio/multi-checkbox selection, Other/freeform drafting, option order and terminal/answered/readonly states. Choice selection only populates the editable legacy composer as a reply; it never submits. The narrow draft adapter validates the canonical prompt and switches to its source thread when needed. The source-thread draft callback is synchronous and has no fake server success contract.

Permission asks retain the exact existing hook predicate and Approve/Deny, then Confirm/Cancel. Canonical answer text determines approved/denied attribution/time, and terminal closure removes actionability. The existing host private-ask/answer filtering stays unchanged. This slice does not widen backend permissions or change the hook's own-human answer validation.

Polls retain single/multi toggle semantics, total-vote percentages, distinct voter counts, up to four avatar marks per option, selected pressed states and every positive tied winner when closed. Only the poll author, or any member for an AI poll, can close it, with confirmation. The existing backend silently no-ops invalid vote/close calls, so even a successful correlated ACK is not proof of mutation.

Actual message/vote/close mutations use required Promise-only correlated `request`. One mounted prompt or poll owns its operation, disables duplicate submissions, reports local errors and waits for canonical state; it never changes room data optimistically. Missing post-ACK confirmation expires after 10 seconds and remains visibly unconfirmed. An accepted unconfirmed reply is not automatically submitted again. Transport timeout/disconnection after queueing is uncertain and cannot be retried while awaiting canonical reconciliation. Poll toggles never retry automatically, and an unconfirmed toggle stays disabled until canonical state resolves its desired target. Known pre-send offline/server refusals permit explicit retry. Canonical answers/removal/terminal closure/poll closure, room/account changes and disposal invalidate old tokens and timers, ignoring late errors. Detached native controls cannot start new actions.

Still pending: thread-card HTML, poll creation dialog, editable composer/submission lifecycle, room shell/history/navigation and F49 app protocol. Native cards use the existing narrow app-navigation callback; they do not migrate Apps. Neither full F20/F21 nor F15–F23/M6 completion is claimed.

Validation is scoped: focused pure tests exercise wire compatibility, limits, projection and command ownership/ACK order. DOM source fixtures cover actual card/choice/permission/poll controls, confirmation, failures, canonical updates and detached callbacks. Integrated type/style/DOM/build/browser/mobile/artifact gates remain root-owned.
