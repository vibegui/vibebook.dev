# Current-main Inbox parity source

This port starts from the `bd76e05` merge of current main's `cbaf3df` Inbox contract. It changes no vanilla source/assets or backend membership queries. `HomeApi.inbox` uses the inferred Hono endpoint with `cache: no-store` and parses unknown JSON with `InboxResult`; mention/task aliases derive from that schema.

The existing single ApplicationInbox now owns a separate 20-second read lease alongside its existing resolve-write lease. Each opening captures account, identity revision and room filter. Close/navigation/identity/disposal cancel both leases and clear private rows. A read revision prevents canceled/replaced responses and ignored-abort completions from refilling newer state; timeout exposes explicit retry. Known 401 revokes document authority through the existing services boundary. No automatic mutation retry or optimistic canonical deletion is added.

AppShell supplies the actual fetched waits, mentions and tasks. Message/epic actions require current binding and exact currently held row ownership, then route through existing services. Wait resolution still checks Personal canonical state and refreshes both Personal and Inbox after acknowledgment. The native sidebar's expanded and collapsed Inbox controls share this same owner with the header control. The UI retains modifier-aware anchors, uses native Heading atoms, exposes loading/error/retry and guards stale connected callbacks.

Source regressions extend the existing owner cohort with ignored-abort timeout/retry, canceled opening/private response, canonical mention/task navigation and known401/account replacement. A real-component DOM source case covers all sections, explicit retry and stale connected controls; the existing identity-replacement fixture is retained with an explicit Inbox HTTP double. No formatter, pure tests, compiler, browser or performance execution is claimed at this checkpoint. Backend mentions membership hardening is separately parent-owned.
