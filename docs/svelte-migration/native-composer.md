# Native room composer

The real room mount renders `Composer` through the native view registry. The host no longer renders textarea/reply/tray/mention/emoji/plus-menu or poll-creation HTML, attaches their delegated/global handlers, owns `attached`/`replyTo`, or mutates the input to fill choices. Its remaining adapter passes canonical room snapshots, scoped Promise requests, typed upload calls and message navigation. The existing board-layout anchor remains `#composer`; editable input stays `#input` for existing room integration and browser fixtures.

The composer preserves Enter versus Shift+Enter/IME, selection-aware mention and emoji insertion, keyboard suggestion/menu navigation, mobile send focus behavior, reply snippets/cancellation, picker/paste/drop, typed file uploads and poll creation. Textarea geometry uses intrinsic sizing/rows and finite Tailwind bounds rather than authored style attributes. Emoji aliases share `shared/emoji.ts`; mentions use canonical/global member aliases plus valid own sandbox names, tolerating nullable sandbox metadata. Paste is scoped to the active chat and does not upload behind unrelated open dialogs or inputs.

`createComposerDrafts` is one document-owned in-memory bag keyed by account, room and thread. It does not duplicate Home's `PersonalSession.draft.ask/create`, use browser storage, or introduce a second account listener. The existing `ensureNativeHome().onIdentityChange` resets it synchronously with the other private owners. Component teardown releases room/request/focus references and preview URLs; original-scope uploads can finish into their account draft without focusing another page. Account reset aborts uploads, invalidates operation epochs, cancels timers and clears private draft records. The bag permits 64 nonempty drafts; clean empty records may be evicted, while a full bag refuses new content visibly rather than silently discarding an unsent draft.

Uploads preserve the supported image/PDF/HTML/Markdown/text/CSV/audio catalog, extension/MIME aliases, screenshot naming and 10 MiB/50 MiB size limits. Media-type parameters are normalized like the existing HTTP route. At most ten attachments and two concurrent requests are admitted; each upload has an independent 20-second owner deadline and AbortSignal. Removal/reset prevents late responses from reappearing. Successful metadata must belong to the scoped account; immutable returned file IDs are used for posting. Blob previews are revoked on removal, completion and unmount. HTTP authorization, secret scanning, rate limits, app/reminder handling and storage policies remain on the Worker. Aborting an HTTP request does not claim that a stored file was deleted. Explicit upload retry can create another immutable version; it never retries automatically.

Message requests retain the exact submitted text/files/reply snapshot and loaded-ID baseline. The UI does not clear on Boolean queue success or ACK alone. A successful correlated ACK plus a newly observed own human message in the same thread with matching normalized text, immutable file-ID set and reply target settles the operation; only an unchanged submitted revision is cleared. Edits made while sending remain intact. File-only messages and replies retain WebSocket semantics. Failed attachments can be removed/retried or left visible while an otherwise valid text/ready-file message is sent.

The current wire result does not carry a message ID. A matching row after a lost ACK could come from another device posting identical text, so timeout/disconnect/server-error outcomes remain uncertain even when a candidate exists. Duplicate submission stays blocked. The user can inspect a scoped matching message/prompt and explicitly keep or discard only the local draft after reviewing the room; no delivery claim or automatic resend is made. Validated prequeue/Refused failures that precede `addMessage` permit explicit retry. Uncorrelated legacy `blocked` events are informational only; correlated command results own operation state.

The existing inferred HTTP `postMessage` endpoint cannot replace this path without a contract/business-rule change: `PostMessageBody` accepts only text/thread, rejects file-only posts, drops unsupported files/reply fields, falls unknown threads back to main and always reopens archived threads. WebSocket messages support attachments/replies, reject unknown threads and preserve the choices/card-answer archived behavior. Its returned authoritative ID is useful to Home but does not provide room-composer parity. No backend protocol or permission rule changes are included here.

Poll creation preserves three initial option fields, two-to-ten nonempty options, 200-character choices, 300-character question and multi-select flag. Form data remains until successful ACK and a new matching own canonical poll plus its same-thread poll message. Unconfirmed results keep the form and require explicit review before retry; canonical room data is never synthesized.

Private ask/reply visibility is now a pure projection shared with the host and composer. Parent lookup includes loaded messages and origins. Reply selection, quote preview and submit validate visibility again; a target that becomes private/unavailable retains typed text while requiring explicit cancellation. Canonical room arrays remain unchanged.

Pending owners remain explicit: thread-card HTML, room shell/header/history/scroll, document/editor surfaces, Agents/Apps and the F49 iframe protocol, viewer/file-access presentation and other remaining host features. This source slice does not claim full F15–F23, M6 or M7 completion. Source pure tests and DOM interaction fixtures are separate from root-owned integrated type/style/DOM/build/browser/mobile/artifact gates.

The authoritative vanilla F17 baseline includes browser dictation, even though the preceding hybrid host omitted it. `speech.ts` validates the small SpeechRecognition/WebKit constructor surface and receives unknown result/error events through a bounded typed projection. A quick Space tap replaces the current selection with a space; a hold of at least 350 ms starts recognition. A following typing key flushes the pending space first, modifiers/IME retain ordinary keyboard behavior, and the mic supports pointer capture/release/cancellation. Recognition uses the current locale, continuous/interim results and the baseline append-to-current-text behavior. Unsupported browsers retain ordinary Space behavior and hide the mic; no server transcription fallback is invented.

Dictation is scoped to the focused native textarea. Editing independently, losing focus/window ownership, hiding the composer, sending, account/room/thread replacement or disposal aborts and invalidates callbacks and hold timers. Late events cannot overwrite a new draft or steal another page's focus. Permission denial is local state. Synthetic speech-controller/DOM fixtures establish state/capability behavior only: they do not establish actual microphone permission, browser speech delivery, network recognition availability or mobile support. Those remain explicit real-browser/manual gates.

The mic also accepts keyboard-only click activation (`detail === 0`) without restarting on the synthetic click following pointer release. Pointer release/cancel/lost-capture requests a normal recognition stop and can retain the final result for the same owner, matching vanilla; blur, Escape, hiding or disposal aborts and invalidates later results. The recording indication remains visible, and keyboard users can stop through Escape, focus changes or sending.

Deleted-thread drafts are recoverable through a compact original-account/room notice and readonly review of text, reply target, attachment metadata/status and poll fields. Copy failures leave the selectable original visible. Explicit Discard removes only an unchanged original-scope local snapshot, aborts its local pending work and frees its bag slot; it does not undo server writes. Canonical target reappearance, account/reset, changed snapshots and component disposal fence stale review actions. Recovery never sends, routes or retargets content.
