# Native room sidebar, header and suggestion outputs

The real room mount uses native Sidebar for expanded and collapsed layouts, RoomThreadHeader for the conversation heading/actions, and SuggestionPreview for `pre:index` previews. Sidebar reuses native RoomStrip, EpicTree, Pins and People. Room marks preserve uploaded icons and finite Studio tint tokens; collapsed rows retain task progress, current selection, wait counts, add affordance, request badge and member marks. Agent and sandbox presence rows now receive schema-derived data, with listening/session deduplication, model/repository labels, context and live plan limits, sandbox owner/state/cost, and a direct scoped action to the existing Agents pane. Sidebar receives no HTML-producing callbacks.

`createRoomMutations` owns account/room-scoped Promise requests for epic create/owner/order/rename/archive/delete and suggestion accept/skip. Canonical snapshots remain authoritative: ACK alone never clears the creation draft or reports a completed order. Waiting is bounded; uncertain transport outcomes keep the original operation and disable repeat mutations until canonical reconciliation or explicit local review. Component-only rail remounts retain the owner and navigation draft. Account/room teardown cancels timers and invalidates late callbacks. Renaming preserves a changed draft; delete confirmations bind the entire canonical target snapshot and close after replacement/removal. All actions call typed services directly rather than clicking hidden host buttons.

A suggestion preview is not an epic or a composer draft. Accept preserves the actual server behavior: remove that suggestion and post the existing generated human request in the main thread so the person's agent can review and create the epic. Skip removes it and opens the next remaining suggestion, or main. The native command includes an optional `expected` canonical suggestion snapshot. Shared identity compares only title, why and ordered tasks; Book rejects a mismatch before splice, persistence, broadcast or message creation. This prevents a previously unseen index shift from accepting another suggestion. Older vanilla index-only commands retain their existing wire behavior. No authorization rule or agent business flow changes.

Native ThreadCards render each source message's canonical `epics.from_msg` entries, archived/task/reply counts, last reply, owner mark and descendant file summaries. Loaded newest-message file identity takes precedence over metadata-only epic summaries; version counts and six-chip overflow remain intact. Partial metadata opens the existing exact-ID viewer adapter. The real Message mount no longer accepts any HTML integration: `LegacyChatIntegrations`, `LegacyChatContent` and the markup adapter are removed. RichContent and InteractiveBody remain their existing native owners. The host's thread-card builder and delegated navigation handlers are gone.

Pending boundaries remain explicit. The room shell owns layout, responsive container/sheet routing, history/deep-message navigation, scroll anchoring and a disposed `mountSheetHandle` adapter for the existing continuous drag geometry. Agents/sandboxes panes, account setup, connections, terminal and F49 application protocol remain separate migration slices. This does not claim full F24–F26/F41–F50, F15–F23, M6 or M7 acceptance. Composer, Viewer and Document ownership is preserved; no new storage, upload, authentication or backend permission behavior is introduced.

Focused pure fixtures cover old/new suggestion wire compatibility, unseen index shifts, canonical/ACK ordering, uncertainty/no retry, scoped disposal and exact descendant file versions. DOM source fixtures cover canonical confirmation replacement, rename waiting, direct archive and safe suggestion controls. Prior sidebar tests retain fold/draft/order/focus/pin behavior while using correlated mutation requests. Type/style/DOM/build/browser/mobile and actual Worker evidence remain separate root gates.

The deletion follow-up refuses `main` and unknown epic IDs in the authoritative Book deletion method before mutation SQL. Existing-ID deletion retains its SQL scope, canonical notification and document-relay revocation. The focused source suite now includes actual Book prototype and correlated-dispatch fixtures (mocked Cloudflare bindings, not real Durable Objects). A real-browser navigation case is authored for 390px sidebar → controlled typed sandbox presence → visible Agents document sheet, asserting entry reuse and one Back; it remains unrun and does not claim a real sandbox lifecycle.
