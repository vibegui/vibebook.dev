# Initialize the actual file-navigation target before insertion

The controlled HTTP browser run `43580081527` reached POST 200 but created a new page at the uploaded file URL. Its owned iframe remained `about:blank`; the reflected name attribute was present while the actual child navigable name did not match. Keeping the submitted form attached did not change that outcome. This does not support disconnected-form cancellation as the cause.

The current [HTML iframe name contract](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-name) assigns the attribute's value to the content navigable when that navigable is created. The old host assigned `frame.name` after DOM insertion, which changed the attribute too late. The correction initializes a public routing name before insertion: native component markup, vanilla HTML templates, fresh vanilla reopen nodes and the controlled HTTP fixture. Native embed generations receive distinct stable names. The host captures the existing name and rejects missing, reserved or changed targets rather than attempting to rename an already opaque window.

Names are routing labels independent of the private grant nonce. Sandbox flags, source/nonce/port checks, POST URL and body, file response headers, retirement and one-grant-per-frame rules are unchanged. The HTTP proof now checks actual child-name equality before submitting, requires no additional page, and retains its original private-read and replacement-refusal assertions. Source diagnosis is supported by the observed target mismatch; successful HTTP rendering and both frontend grants still require the next real browser run.
