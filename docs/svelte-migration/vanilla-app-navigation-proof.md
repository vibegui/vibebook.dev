# Both frontend document-authority probes

The existing real Worker App navigation fixture now accepts an explicit typed UI driver. Its default remains native Svelte. A second driver opens the plain `/b/ROOM` vanilla URL, selects the actual `.ptabs` Apps control, opens the canonical room-App button, and observes the actual `#appsPane iframe.connFrame` produced by `renderConnApp`. The driver supplies selectors and real UI actions only; it cannot supply canonical data, responses, a bridge or an authorization decision.

Both variants use the same fixture setup/protocol implementation: supported HTTP creates a synthetic room, the controlled provider must first refuse the DENY upload, R2 accepts the ALLOW document, Book stores a random canonical message, and a real click grants the initial uploaded HTTP document a read. Only its private response can reveal the marker. A real second loopback origin then replaces the same iframe element and WindowProxy; opaque origin and explicit read refusal remain mandatory. Marker artifacts contain only its SHA256, never its private value.

The integrated application cohort runs the two probes as separate independent audits after the existing core. Failure in one does not suppress the other. The standalone entry also runs both and writes an aggregate verdict; any inherited read or inconclusive result fails the aggregate. Native evidence keeps `native-app-navigation.json`; vanilla writes `vanilla-app-navigation.json`, with an explicit `variant` in each. No initial-read, HTTP form, vanilla/native integration, BFCache or browser security acceptance is claimed by this unexecuted source checkpoint.
