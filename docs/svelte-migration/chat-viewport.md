# ChatViewport source extraction

The typed controller owns the actual room chat's sixty-message window, read-only older requests (the existing backend supplies one hundred per page), per-thread completion/fill bookkeeping, bounded fifteen-page message search, delayed reveal/attention callbacks, bottom pinning and scroll anchoring. It uses the existing privacy-filtered native Chat projection and does not replace message/attachment/card components or their actions. The host retains its renderer, URL/history and panel actions; it delegates real window selection, older events, scroll surface attachment and search to this controller. The old window/pending-search/observer globals and pagination implementations are removed.

`surface.ts` is measurement/scroll interop only. It subscribes to the actual chat container, current children, subtree additions and font completion, and releases listeners/ResizeObserver/MutationObserver together. Content growing below the reader does not unpin; upward scrolling does. Prepend uses the previous scrollTop plus the actual scrollHeight delta; state refresh while reading preserves scrollTop. Room/account/Book generation/thread replacement disposes scoped observer callbacks and scheduled reveal/attention work. The existing message highlight event is preserved. No stylesheet, geometry or DOM builder was added.

Fresh partial reconnect snapshots invalidate cached completion/fill assumptions. A failed queued read or ten-second missing response releases read ownership with an offline notice and allows explicit recovery, without automatic resend. The initial-fill attempt marker survives refusal/timeout so passive receipt/typing/status renders cannot retry it; explicit loadOlder/go or a fresh snapshot can initiate another read. These are read-only history requests; Boolean send still only means queued. Mutation ACK/canonical behavior stays in its existing feature owners. Exact account/room/connection identity fences are distinct from valid current canonical message data.

Pure source fixtures cover window growth, initial-fill coalescing and fresh snapshot recovery, height-delta anchoring, upward-only unpinning, late growth, fifteen-page limits, reveal/attention cancellation, refused/missing pages, detached callbacks and successful off-window reveal. They use explicit scroll and connection-model doubles; they are not DOM/browser or real socket evidence. A separate real-component DOM source fixture mounts Chat with an empty failed fill and clicks its existing older control to prove reachable explicit retry. Host lifecycle fixtures retain real source cleanup coverage with the new controller reset. All formatter/pure/type/style/DOM/build/browser gates remain unrun at this checkpoint under root resource hold. RootRoomSession commits bb909e8/2d3e4fb are prerequisites; Account/Agents/Apps source remains separately queued and must preserve their newer callbacks during porting.
