# Native Agents and Sandbox source slice

This slice mounts the typed native Agents pane, personal AgentSettings, header trigger, room setup/start banners, incoming asks, invited-person four-step welcome and sandbox terminal through the real host registry. The host no longer builds their HTML, installs delegated action handlers, loads global xterm scripts/CSS, renders context meters, or owns their request/poll/terminal resources. The remaining `renderAgentSurfaces`, `syncNativeAgents` and `loadRoomAgents` functions are temporary AppRoot mount/event facades; `roomAgents` is a metadata projection for existing native Sidebar and Composer props. `epicBusy` formats the already-native `threadWorkers` projection for the pending SidebarBridge shell contract.

## Ownership and wire behavior

A document service owns one account grant/credential actor and scoped room actors. The existing Personal identity-reset callback synchronously disposes these owners. Leaving a room clears its full room/messages projection, stops reads/polls/runner probes and closes its terminal; only bounded unresolved mutation records remain for explicit review in their original scope. New writes stop once the retained room limit is reached. Component teardown cannot redirect operations or callbacks into another account, room, VM or terminal generation.

HTTP methods come from the inferred Hono client; every response is parsed against shared runtime schemas. No backend runtime is imported into the browser, no authorization rule or command protocol changes. Agent toggle uses the authoritative `claude_on` returned after the member update. Queue dismissal uses correlated Promise request plus canonical queue absence. Permission answers are excluded using both loaded messages and origins. The native queue initially shows four rows, with incremental expansion and exact source-thread navigation.

Grant removal and immutable VM disappearance invalidate obsolete operations. VM create requires its returned exact ID/VM/name plus the refreshed own list. An ACK-less create never claims an unrelated new machine as its result. Power changes require their own ACK and desired canonical state; a later old pause cannot silently unlock a new start. Timeout/disconnect/storage/external allocation uncertainty remains unconfirmed with no automatic resend. Only established pre-write refusals become retryable failures. VM setup has a five-minute owner deadline to preserve the existing foreground setup duration. Polling runs only while the pane is active and machines are being prepared or changing state; reads are independently bounded even if a transport ignores AbortSignal.

Server 401/403 denials latch independently of cached room membership. Only a successful fresh authorized endpoint read clears the corresponding denial. After a known global session rejection, recovery also requires no-store identity-bearing Me proof matching the actor’s captured account before and after the metadata read; identity-free Agents/list payloads cannot restore authority for a replaced cookie. Local membership refusals preserve account grant authority. Canonical membership removal closes the terminal, clears metadata and invalidates pending room actions synchronously. Credentials are transient password inputs, cleared before requests, never persisted in public actor state or rendered in errors. Historical setup logs are bounded and defensively redact recognizable credential assignments; server secret storage/redaction behavior is unchanged.

## Terminal vendor amendment

The explicit 2026-11-13 maintainer approval and exact artifact pins/digests are recorded in `xterm-vendor-amendment-proposal.md`, the full migration plan and `svelte/styles/vendor-css.json`. Xterm 5.5.0 and addon-fit 0.10.0 are lazily imported ESM dependencies. Their exact structural stylesheet enters only through the sole Tailwind entry. Vendor-generated internal geometry remains inside the terminal mount; surrounding application UI is Tailwind/atoms. No arbitrary vendor theme, palette or first-party stylesheet exception is added.

The renderer resolves Studio foreground/background/selection with the browser canvas, including computed CSS Color 4 values unsupported by xterm's older parser. Font options come from computed Studio monospace typography and wait for font loading. Resize/theme/font observers and subscription handles are released on normal teardown and initial construction errors. Renderer startup, PTY credential acquisition and connection readiness each have an owner deadline. Late renderer creation disposes its result. Endpoint validation binds the returned official WSS URL to the exact VM, with loopback-only mock support for local development. The scoped PTY token remains private to WebSocket protocol setup. Binary input/output, JSON resize/session-info/exited/error, mobile special keys, keyboard activation and close/reopen preserve the baseline protocol; reconnect is explicit.

## Verification boundaries

`native-agents.test.ts` contains focused pure owner/denial/deadline/uncertainty/endpoint/credential/terminal-ticket fixtures. `terminal-vendor-policy.test.ts` verifies exact installed bytes and rejects broader packages/scopes/sources/digests; existing style-policy fixtures cover the sole entry and narrow semantic option adapter. Real component interaction source is appended to `ui-panels.test.ts` for grant canonical disappearance, late rejection, same-ID VM replacement and password clearing.

`native-agents-browser.ts` uses a real loopback Worker room and the actual pinned native xterm renderer, with explicitly controlled cloud-list/credential and PTY protocol fixtures. It checks resolved RGB equality in both Studio modes, actual CommitMono font loading, binary keyboard/mobile-key input, resize, disconnect/no automatic reconnect, close/reopen and navigation disposal. It does not claim a paid Freestyle VM, real remote Claude delivery, real secret provider validation or local runner launch. Runtime/type/style/DOM/build/browser results must be recorded separately after execution; source fixtures alone are not acceptance. MCP Apps/Connections and final AppRoot ownership remain separately pending, so this is not a full M6/M7 claim.
