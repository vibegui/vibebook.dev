# Native room Apps and MCP connections

This slice replaces the Svelte host's Apps catalog, connection forms, connection app iframe toolbar, app permission markup and handwritten JSON-RPC dispatcher. It does not change vanilla's default entry, the authenticated backend routes, MCP server selection, private/room connection scopes, OAuth, or the server's resource CSP generation.

The baseline is `svelte/legacy/host.js` at b00c22e, functions `renderApps`, `loadConns`, `roomApps`, `renderConns`, `renderConnApp`, `appAsk`, `vbRead`, `vbCall`, `makeHost`, `embedHost` and `mountApp`, plus its global `message` listener. Room apps select the newest canonical `apps/<name>.html` attachment. Remote resources are fetched by the authenticated Worker's existing `/connections/:cid/ui`; `src/mcpconn.ts` injects CSP before resource content. Browser frames stay opaque (`allow-scripts allow-forms`, no same-origin). Chat embeds keep their stricter existing sandbox and native geometry/permission UI.

The native boundary consists of:

- `api.ts`: inferred existing Hono connection requests and shared runtime response schemas. OAuth remains real browser navigation to the existing same-origin sign-in route; raw server URLs, grants and credentials never enter catalog data.
- `session.ts`: room/account/Book-connection ownership, canonical HTTP catalog reads, independent form drafts, screen/all-tools filtering, mutation uncertainty and explicit review. A known membership loss latches the owner denied until a new authenticated owner is created.
- `AppsPanel` and `AppFrame`: Tailwind atoms, native confirmation UI, pinning, reload/back, server sign-in/out, exact app/file version ownership and iframe disposal. Read/update/error states stay accessible and text is escaped by Svelte. No first-party HTML fragments or style family are added.
- `bridge.ts` plus `transport.ts`: installed `@modelcontextprotocol/ext-apps` **1.7.4** `AppBridge` handles protocol version negotiation, request schemas, handlers and notifications. A host transport is necessary because the SDK's public `PostMessageTransport` documents source-window checks but does not express the existing mandatory null-origin policy. The native transport requires both the exact live frame WindowProxy and `event.origin === 'null'`, an unchanged owner and an opaque sandbox. It validates the JSON-RPC envelope and SDK method contracts without imposing a new deep traversal or payload budget on opaque remote tool arguments. Large legitimate Studio/document arguments remain opaque and are forwarded unchanged. Pending asynchronous dispatch is bounded per frame with explicit pre-dispatch errors. The old `{vbEmbed:1,h|send}` envelope and role-less/id-less request compatibility are narrow adapters into the same owned operations, not another JSON-RPC implementation.
- `tools.ts` and `embed.ts`: the existing room read/post/tasks/metrics/connections tools with typed canonical data and correlated room-command results. The same bridge is mounted per native chat embed; no global host registry or wildcard frame discovery remains.

Permission parity is deliberate. Room/embed writes and external links ask the person. A room/embed call to _any_ connection tool always asks, including tools advertised as read-only, because the remote server's hint is not authority to disclose the person's data. A selected remote panel's initial tool call and its own same-server `tools/call` retain the existing behavior without a new approval workflow. Context writes use the same existing per-tool endpoint and 4000-character limit. No new server business rules are introduced. A queued WebSocket command is not reported as success: the native tool adapter uses the existing correlated request result. Timeouts do not imply rollback; no mutation is automatically retried.

The SDK client argument is deliberately `null`: the browser does not own a direct remote MCP session or token. Only the existing authenticated Worker endpoints perform remote resource/tool access. The host advertises tools, links, text messages/context and logging as supported by its handlers; it does not advertise remote resource/list/read, downloads, sampling, camera or other capabilities absent from the baseline. No endpoint is invented to satisfy an SDK capability.

Source, strict type/compiler/style tests and actual iframe/remote-provider runtime gates remain separate. Source authoring has not started a Worker/browser/build or installed dependencies. Real OAuth/provider errors, resource CSP, clipboard/open-link gestures, canonical permission changes, multiple embeds and mobile layout require the parent's sequential runtime verification.

SDK/bridge code is dynamically imported only when an owned panel/embedded frame mounts. The bounded import owner ignores late completion after timeout, scope replacement, known denial or disposal; no SDK host is installed globally. Actual Vite dependency-optimizer and browser memory/startup behavior remain measured runtime gates. Known membership refusal on connection endpoints latches the Book-connection authority shared by its frames, cancels native consent, clears cached room reuse and hides the private resource. Metrics/report403 is not membership evidence. Denied panels expose an explicit fresh-access check with no replay. Consent buttons carry immutable per-question tokens, and app pins wait for canonical desired state with bounded uncertainty rather than treating an ACK as confirmation.

The existing global `401 {error:'unauthenticated'}` is authoritative signed-out evidence on every API, including metrics. It clears the frame authority as well. This is distinct from a remote connection's `401 sign_in:true`, which retains its separate server sign-in action, and a report/metrics403, which does not prove membership loss.
