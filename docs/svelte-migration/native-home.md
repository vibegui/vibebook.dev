# Native Home, Archive and room navigation

Status: source work in progress. Vanilla remains default. This slice does not complete the full migration or establish deployed/browser acceptance.

The opt-in application mounts native Home and Archive through the existing application bootstrap, rather than adding unused standalone pages. Native room navigation stays mounted across page transitions. The application router owns native history changes and explicitly hands room/editor/viewer behavior to the remaining room integration. Room→Home disposes page views and the room transport; Back mounts a fresh room transport. Delayed room message/file landings carry room and router generation ownership. Legacy viewer/sheet dismissal during navigation does not issue a late `history.back()`.

`features/home/personal.ts` owns the account cache, clock-derived busy indicators, read highwater and drafts. Page sessions own requests and late navigation effects. An invalidation during `/api/me` cannot replace the cache with that older request's result; it coalesces a subsequent read. Changing account clears private drafts and invalidates pending agent responses. Failed reads retain earlier canonical data and offer explicit retry.

There are deliberately two room orders: desktop Home and the rail use explicit position then creation time; mobile Home and the three-room strip use last-opened then updated time. Native tiles retain human/agent unread distinctions, waits, busy expiry, cloud sandbox markers, icon/tint settings and room membership display. Search combines local room names/folders with typed remote epic/message/file snippets and explicit partial failures. Links preserve thread/message/file identity and `ui=svelte`; modifier-click navigation remains available.

The Home composer routes the exact submitted draft, offers all returned destinations and a new-room alternative, then posts to the selected room/epic or creates a room. Editing invalidates stale suggestions. Page disposal suppresses late draft clearing, notices and navigation; it does not claim a server write was rolled back. Unknown invitees are shown only on the resulting room. Create drafts belong to the account and survive closing/remounting the dialog. Mutations have no automatic retry.

Room archive, tint, icon, order, current-room rename and ask resolution wait for canonical data. Successful HTTP/command acknowledgement alone is insufficient because account cache invalidation happens asynchronously. Bounded readbacks reconcile successful writes; absent/reversed desired state becomes explicitly unconfirmed after ten seconds and allows deliberate recovery. Remote room removal obsoletes its pending settings action. Rename is offered only for the connected current room, using its existing typed title command. No endpoint for renaming arbitrary rooms was invented. Only `m` asks have a resolve control; task/agent waits retain their thread/message links.

The owned legacy Home/phone Home, route composer, create/archive dialogs, archived list, rail/switcher search and room-strip HTML/listeners are removed from the Svelte host. Their replacements use typed Svelte components, shared atoms and complete Tailwind utility strings, with no icon/HTML rendering bridge. The shared Heading atom explicitly protects native headings from the hybrid shell's historical heading declarations.

A scoped disposable **pending legacy adapter** remains for account/profile photo and name, friends management, sign-in history, device lock, agent setup and agent connection revocation. It is outside native Home ownership, retains existing behavior, and guards async results against account changes/disconnected overlays. The rest of the room/editor/viewer and other remaining panels are still migration work. The hybrid shell's legacy stylesheet therefore remains a full-migration gap; this slice does not claim the final one-stylesheet gate.
